## Durable lessons (highest-value first)

### L1 — Writing `.github/workflows/*` from a web sandbox: use the ext-github Contents-PUT endpoint (CANDIDATE AGENTS RULE)
Both the git-push OAuth token AND the GitHub MCP write tools lack the
`workflow` scope in Claude-Code-on-the-web (anthropics/claude-code #61189).
Verified this is a **regression**, not an immutable limit (this repo's own
2026-05-28 web session pushed `unit-tests.yml` over git). The durable
solution now exists: the jentic PAT was granted **Contents + Workflows
write** and wired into the `ext-github` skill as
`create_or_update_file_contents.json` (`op_12ee1daaad73b14b`, SKILL.md §8).
Call contract: base64 the whole file, pass the current blob `sha` (UPDATE),
target the feature branch, then `git fetch && git reset --hard origin/<branch>`
to reconcile. **Rule text:** "To create/edit any `.github/workflows/*` file
from a web sandbox, use the ext-github Contents-PUT endpoint — git push and
GitHub MCP both 403/reject on the missing `workflow` scope."

### L2 — Any subagent that runs git MUST use `isolation: worktree` (CANDIDATE AGENTS RULE)
The first stack-resolution subagent ran on the **shared** clone and
`git checkout`ed a different branch mid-run, which the stop-hook then
flagged as "uncommitted changes" that were actually its in-flight merge.
Every subsequent resolution subagent used `isolation: worktree` — clean.
**Rule text:** "When dispatching a subagent that performs git operations
(checkout/merge/commit/push), pass `isolation: worktree`. A non-isolated
subagent shares the lead's working tree and will collide with concurrent
lead git state."

### L3 — Use `actions_get` (single run), not `actions_list`, for run status
`mcp__github__actions_list` returned 380KB+ payloads that overflowed the
tool-result cap every time and had to be sliced from a saved file.
`mcp__github__actions_get` method `get_workflow_run` returns one run's
status compactly. Reserve `actions_list` for when the list itself is needed
(then parse from the persisted file).

### L4 — When a fix is "confirm on a live run", bake the confirming diagnostics INTO the fix
The provider-SA fix carried a broadened failure-path dump (describe
providerrevision / `get lock -o yaml` / crossplane logs). Validation-1
failed — but that dump captured the crossplane Lock condition
`cannot build DAG: node ...provider-family-aws already exists`, which
**confirmed** the duplicate-Provider root cause (resolving adversarial
reviewer #1's "is this really the duplicate, or a package-manager-wide
stall?" objection) instead of leaving it a hypothesis. The diagnostics did
double duty: they were the evidence the reviewer demanded, gathered on the
very run that tested the fix.

### L5 — Crossplane v2: the explicit family Provider must be named the dependency-derived name (ADR-worthy)
A child provider (`provider-aws-eks/iam/acm/route53`) auto-creates its
family dependency Provider with a name **deterministically derived from the
package's own `metadata.name`** (`upbound-provider-family-aws`). If you
ALSO declare an explicit family Provider under a *different* name
(`provider-family-aws`), you get TWO Provider objects owning one package →
the package-manager Lock cannot build the dependency DAG (`node ... already
exists`) → no provider runtimes → no Deployment → no ServiceAccount → the
IRSA-pinned SA never appears, every MR stalls. Fix = name the explicit
Provider exactly the dependency name so the children de-dupe onto it; add
`depends_on` so the family is applied+Healthy before the children (kills the
create race); add an idempotent **orphan-cleanup** (`kubectl delete
provider provider-family-aws --ignore-not-found`) so it self-heals a wedged
cluster in-place without a destroy; and assert exactly ONE Provider owns the
package so a re-introduced duplicate fails loud. This supersedes the partial
OI-2026-06-05-3/4 fixes. Confirmed live: run 27056287208.

### L6 — Adversarial subagents earn their cost on "hypothesis-as-conclusion"

### L7 — A read-only investigation subagent can de-risk a whole merge-train cheaply

(none touch `crossplane/**` or `tests/chainsaw/**`) and that `chainsaw-verify`
is non-required (#144 merged with it red) — turning a feared multi-cycle
chainsaw-gated train into five fast conflict-resolve-and-merge steps.
