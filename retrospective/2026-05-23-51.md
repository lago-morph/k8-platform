## Part 1 — what happened

### Phase A — user-driven merge cascade

User merged the stack in order: #41 → #42 → #43 → #44 → #45 → #49. After each merge, a webhook notification arrived. The pattern I followed for each: `git fetch origin main`, `git checkout <next-PR>`, `git merge origin/main`, additive-resolve `tests/unit/run.sh` if conflicted, `git push`. Roughly 30 seconds per PR.

Conflict pattern observation: the first three merges (`#42` → `#43` → `#44`'s post-#43-merge state) all conflicted on `tests/unit/run.sh` because each parent had added a new `run_suite` line and main moved each time. The fourth (`#44` after `#43` merged) was clean — by that point each new `run_suite` entry had already been incorporated upstream. Same pattern continued: `#45`'s merge was clean (handoff content non-overlapping with main's recent moves), and `#49`'s was clean (the fmt fixes were already on main via the stack).

The two skills from -50 (`additive-conflict-resolver` and `pr-stack-rebase-from-main`) got exercised exactly as their specs described. Both held up; no spec updates needed.

### Phase B — first chainsaw workflow run

When #49 pushed (last in the cascade), it merged main which included `chainsaw.yml` from the now-merged #41. The path filter matched (`.github/workflows/chainsaw.yml`, `tests/chainsaw/**`, `crossplane/**` all changed), so the workflow fired for the first time ever.

It died at step 2 ("Install kind"):
```
chmod: changing permissions of '/usr/local/bin/kind': Operation not permitted
```

GH-hosted `ubuntu-24.04` runners have `/usr/local/bin/` root-owned. The `unit-tests.yml` workflow shipped in PR #47 had this correct (used `sudo curl` + `sudo chmod` for yq). The `chainsaw.yml` workflow shipped in PR #41 missed the `sudo`. That mismatch sat through the entire authoring + adversarial review + merge of the phase-2a stack, undetected, because the workflow never actually ran until #49's merge brought its trigger files together with a real push.

Fix: 3-line patch — added `sudo` to the two `curl -o /usr/local/bin/kind` + `chmod +x` lines and the `install -m 0755` of the chainsaw binary. Shipped as PR #51 off main. Test plan in PR body acknowledges "first real run" hasn't happened yet.
