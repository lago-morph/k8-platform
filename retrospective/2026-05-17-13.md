## Part 1 — what happened

### Phase 1 — Parallel research in isolated worktrees

The user asked for two summary documents (workflow/functionality and project status) backed by **lots** of diagrams, plus a run log of how the multi-agent process went, all in one PR. Two `general-purpose` subagents were dispatched **in parallel** with `isolation: "worktree"` so they couldn't collide on the filesystem. Each agent was given an explicit input list (all `*.md`, all `.github/workflows/`, full PR + Issue history via GitHub MCP, repo subtrees relevant to its question), an output structure with mandatory Mermaid diagrams, and a 5-line report-back contract.

Total wall-clock for Phase 1 was about 6 minutes (longest of the two). Functionality doc landed at 654 lines with 7+ diagrams; status doc at 354 lines with 7 diagrams. Files were copied out of the agents' worktrees into the orchestrator's main worktree before the review loop began.

### Phase 2 — Fresh-context review loop

Three review rounds ran serially. Each round was a **brand-new subagent** with no memory of prior rounds. Each was forced to label findings `major` / `minor_factual` / `cosmetic`, and later rounds were forbidden from raising cosmetic items.

- **Round 1** found 15 issues (4 major). Major findings were all real and load-bearing — e.g., the status doc claimed `cert-manager` was installed as a Helm release on the management cluster, while `terraform/management/helm.tf` actually has only 4 `helm_release`s (no cert-manager) and `irsa.tf` line 149 explicitly says cert-manager is not installed.
- **Round 2** found 6 minor-factual issues (0 major, 0 regressions). Caught the `terraform/management/` file count (claimed 9, actual 8 `.tf` + `tfvars.example`), an internal date contradiction (PR #8 was 2026-05-03 in one row, 2026-05-04 in the same doc's PR table), and a fictitious 🟡 status icon claimed to exist in `ai/handoff.md`.
- **Round 3** returned `clean` (0 findings). Loop terminated.

The orchestrator independently verified every claim labelled `major` before applying any edit (`grep -E '^resource "helm_release"' terraform/management/helm.tf`, `wc -l`, `ls .claude/skills/`). This is the critical safety net — a reviewer can be confidently wrong, and a docs-changing edit must not be made on the reviewer's say-so alone.

### Phase 3 — PR #12 lifecycle

Opened as a finalized PR (not draft — per the user's explicit instruction overriding the default), subscribed via `subscribe_pr_activity`. No CI triggers fire for non-`test/**` branches per the repo's branch policy, so the "pending" status was expected and not a failure. PR merged within minutes. The session was auto-unsubscribed.

### Phase 4 — User-reported mermaid regression → PR #13

The user pasted a screenshot showing **two mermaid diagrams failed to render** on GitHub with `Parse error on line 2: Expecting 'SQE', 'TAGEND', 'UNICODE_TEXT', 'TEXT', 'TAGSTART', got 'PIPE'`. Root cause: literal `|` characters inside mermaid node `[...]` labels (`feat|fix|chore|test`). Mermaid reserves `|` for edge-label syntax. A grep-and-classify pass on every `|` inside `mermaid` fenced blocks distinguished the two broken cases from the many legitimate `-->|yes|` edge labels. Fix was a 2-character change × 2 lines → new branch, PR, merge.

The mermaid failure had survived **three rounds of fact-checking subagents** because the reviewers were checking *factual* claims against source-of-truth, not *rendering* of the generated diagrams.

## Part 3 — agents-file suggestions

See [./2026-05-17-13/AGENTS-suggestions.md](./2026-05-17-13/AGENTS-suggestions.md).

Highlights:

- Always render-test mermaid diagrams against GitHub before reporting docs-changes as done.
- Document agents should be told to escape `|` inside mermaid node labels.
- When the user explicitly asks for a finalized PR, ignore the default "draft PR" rule.
- Worktree-isolated parallel research is the default for any task that produces independent artifacts.
- Fresh-context review loops require severity discipline OR they never terminate.

## Part 4 — proposed ADRs

Architectural decisions made in this session that the user *may* want to formalize. Titles only.

- **ADR: Commit-hash-anchored summary artifact convention.** Filenames in `summary/` use `{kind}-{date}-{hash}.md` and never overwrite an existing-for-same-hash artifact in place; consistency is restored via the review loop, not silent rewrites.
- **ADR: Fresh-context multi-pass review for generated docs.** Default review process for any AI-generated long-form document is N≥2 fresh-context reviewers with explicit severity labels; loop terminates on `clean`.
- **ADR: Worktree isolation as the default for parallel subagent fanout.** Any subagent that writes files runs in `isolation: "worktree"` unless there is a specific reason to share a tree.
- **ADR: Render verification is a separate review pass.** Fact-check reviewers do not verify rendering; a render pass is required before declaring a docs PR done.

Use the `adr` skill (if/when added) to author any of these.

## Anti-pattern reminders for next session

- Fact-checking ≠ rendering. The review loop will not catch a busted mermaid diagram. Add a render-verification step.
- Squash-merge erases per-commit history. If the retrospective wants to see the round-by-round commit trail, capture it BEFORE the merge (or read it from the run-log file in the repo).
- `mcp__github__pull_request_read get_status` returning `pending` with `total_count: 0` is **not** a failure — it just means no CI registered itself. Don't treat it as red.
- "Create a PR as a draft" is the default rule; user-explicit "make it a finalized PR" overrides. Don't be timid about overriding when explicit.
