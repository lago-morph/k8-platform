## Part 3 — agents-file suggestions

### Suggestion 1: Verify reachability via CI before assuming the sandbox path — `AGENTS-MD-bfd8a568f5`
- **Per-rule file**: [./2026-06-05-148/AGENTS-MD-bfd8a568f5-verify-reachability-before-assuming-sandbox-path.md](./2026-06-05-148/AGENTS-MD-bfd8a568f5-verify-reachability-before-assuming-sandbox-path.md)

**Proposed agent instruction:**
> **Verify reachability via CI before assuming the sandbox can reach a cluster service.** "When a handoff or runbook says a cluster service is reachable 'directly from the sandbox', probe it for THIS sandbox first; a clean TLS handshake then 503/403 means you reached a proxy, not the service. If the sandbox can't reach it but CI can (read-only `verify` dispatch), drive the action from CI (§10.1)."
>
> *Grounded in: auto-007 — the handoff's "sandbox has permissive egress, call ArgoCD directly" was false in this sandbox; CI verify proved ArgoCD healthy while the sandbox 503'd.*

**Justification:** Acting on the stale "reachable from the sandbox" claim cost a polling detour, a wrong crashloop hypothesis, and a dead-end workflow attempt; one cheap probe up front avoids mis-attributing an environmental boundary to a service outage. Reachability is per-sandbox, not durable.

### Suggestion 2: Cannot modify workflows without scope — `AGENTS-MD-44adc394f1`
- **Per-rule file**: [./2026-06-05-148/AGENTS-MD-44adc394f1-cannot-modify-workflows-without-scope.md](./2026-06-05-148/AGENTS-MD-44adc394f1-cannot-modify-workflows-without-scope.md)

**Proposed agent instruction:**
> **Don't assume you can add or edit a `.github/workflows/` file; deliver it as a runbook doc if you can't.** "`git push` touching `.github/workflows/` is rejected without the `workflow` OAuth scope, and `create_or_update_file` 404s on workflow paths without the App's `workflows` permission. If both fail, ship the YAML in a `docs/runbooks/` doc + log to open-issues; don't keep retrying."
>
> *Grounded in: auto-007 — adding `argocd-app-sync.yml` was blocked by both paths.*

**Justification:** Two failed write cycles + a branch cleanup before realizing the constraint; knowing it up front reframes a workflow-dependent unblock as a runbook deliverable. Zero marginal cost; saves dead-end attempts.

### Suggestion 3: Strip whitespace from injected AWS creds — `AGENTS-MD-c0737c7eed`
- **Per-rule file**: [./2026-06-05-148/AGENTS-MD-c0737c7eed-strip-whitespace-from-injected-aws-creds.md](./2026-06-05-148/AGENTS-MD-c0737c7eed-strip-whitespace-from-injected-aws-creds.md)

**Proposed agent instruction:**
> **Strip whitespace from sandbox-injected AWS credentials before use.** "Check `AWS_ACCESS_KEY_ID`==20 and `AWS_SECRET_ACCESS_KEY`==40 chars; if longer, strip with `tr -d '[:space:]'`. A stray space yields `IncompleteSignature`/`SignatureDoesNotMatch` that looks like bad creds but isn't — and it's a SANDBOX artifact, so don't conclude CI's account creds are bad."
>
> *Grounded in: auto-007 — injected key was 21 / secret 41 chars; every call failed until stripped.*

**Justification:** The cryptic SigV4 error reads like an invalid key and invites a wrong "rotated creds" conclusion; the 20/40 length tell + a one-line fix resolves it in seconds.

### Suggestion 4: Don't dump huge MCP Actions responses — `AGENTS-MD-bc6cf31b45`
- **Per-rule file**: [./2026-06-05-148/AGENTS-MD-bc6cf31b45-no-huge-mcp-actions-responses-in-context.md](./2026-06-05-148/AGENTS-MD-bc6cf31b45-no-huge-mcp-actions-responses-in-context.md)

**Proposed agent instruction:**
> **Don't dump huge MCP Actions responses into context; parse the saved file.** "`actions_list`/`actions_get` return ~380KB (embedded repo objects). When the harness saves an oversized result, extract the run id/status with a one-line `python3` slice of that file; don't re-issue the call to re-read it, and don't list when you need one run's status."
>
> *Grounded in: auto-007 — repeated 380KB responses to learn one `status` field.*

**Justification:** Each status check already re-uploads the whole conversation (§6.10); a 380KB response to read `status: completed` doubles the waste and recurs per poll. Parsing the saved file is one cheap Bash call.

### Suggestion 5: No blind live-coupled Crossplane infra — `AGENTS-MD-de244e7b40`
- **Per-rule file**: [./2026-06-05-148/AGENTS-MD-de244e7b40-no-blind-live-coupled-crossplane-infra.md](./2026-06-05-148/AGENTS-MD-de244e7b40-no-blind-live-coupled-crossplane-infra.md)

**Proposed agent instruction:**
> **Don't author live-coupled Crossplane spoke/cross-cluster infra blind — build it against the live cluster.** "Work depending on late XR `status`, OIDC thumbprints, account-id-in-ARN, or an uninstalled provider must be iterated live, not authored as final manifests (P&T can't gate on empty status). Split into a separate XR/Composition consuming the ready cluster's status; capture exact MR shapes in a runbook. Author the static CI-verifiable parts now."
>
> *Grounded in: auto-007 — 5 reviewers caught thumbprint/separate-Composition/account-id/provider-kubernetes blockers before code shipped.*

**Justification:** The "build everything" instinct produces confidently-wrong manifests for live-coupled infra; routing that half to a runbook preserves throughput while avoiding first-sync failures that cost a 20-min reconcile per debug cycle.
