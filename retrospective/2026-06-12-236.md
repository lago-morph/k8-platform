## Part 3 — remedy proposals (classified per `ai/LESSONS.md` §3)

Most of this session's lessons already shipped as mechanical checks **in the same PRs as their fixes** (the §3 protocol working as intended): the catch-block drift test, `test_keycloak_admin_secret_source.sh` (self-flagging quarantine), `test_keycloak_realm_json.sh` (comment fields + `TODO_` values), `test_keycloak_apps.sh` KC_HOSTNAME pins, `test_rds_live_check_vpc_logic.sh` (stubbed-CLI bool shapes). What remains:

### Proposal 1 — validate `commit_sha` dispatch inputs in the PreToolUse hook — class (a) mechanical check

**Failure**: I dispatched chainsaw with a hallucinated full SHA (typed `b3f0363c2f0c…` from memory; actual `b3f0363c33c…`), caught only by a post-hoc `git rev-parse`, costing a cancel + re-dispatch. The SHA-verifier gate would have silently never matched.
**Check design**: extend the existing chainsaw PreToolUse hook (`scripts/pre-chainsaw-audit-hook.sh`) to parse any `commit_sha` input in an `actions_run_trigger` dispatch and fail the call unless (1) `git cat-file -e <sha>^{commit}` succeeds locally and (2) the SHA equals `git rev-parse origin/<ref>` for the dispatched ref. Fail-closed, ~5 lines. Audit-before-enforce: only chainsaw dispatches carry `commit_sha` today.

### Proposal 2 — repo-wide `TODO_`-placeholder lint for runtime-consumed values — class (a) mechanical check

**Failure class**: #233 — a `TODO_…` value committed in a runtime-consumed manifest fails closed at boot, but only live. `test_keycloak_realm_json.sh` covers one file; the class can occur anywhere under `platform-services/`, `clusters/`, `argocd/`.
**Check design**: push-gated unit lint scanning YAML *scalar values* (not comments) under those trees for `TODO_`/`PLACEHOLDER_` tokens, with an explicit allowlist for the two known-inert chart-overridden values (`values.yaml` `PLACEHOLDER_DOMAIN`/`PLACEHOLDER_DB_HOST`, which the ApplicationSet/extraEnvVarsSecret override — the lint forces every new placeholder to either be inert-by-override and allowlisted with a comment, or absent). Must land green in the same PR (audit first; the two known placeholders are the only expected hits).

### Proposal 3 — `--output text` boolean comparison lint — class (a) mechanical check (narrow)

**Failure class**: #235 — `aws … --output text` prints Python-capitalized `True`/`False`; comparing against lowercase literals silently inverts oracles. **Check design**: unit lint over `scripts/` + `tests/` flagging any `aws` invocation with `--output text` whose query path ends in a known-boolean field (or whose result is compared within the same pipeline to a lowercase `"true"`/`"false"` literal) unless piped through `tr '[:upper:]' '[:lower:]'` or queried via `--output json | jq`. If the pattern proves too fuzzy to lint cleanly, fall back to class (b): one line in `ai/environment.md` §"AWS CLI" (not AGENTS — it is environment fact, not judgment).

### Proposal 4 — incomplete-revert verification — class (b) judgment rule (owner decision)

**Failure**: #231 — the OI-2026-06-12-1 chain revert (3 commits reverted) missed the keycloak-admin ES swap that one of those commits contained; the gap shipped to main and cost a live convergence round. Proposed one-liner for the owner: *"A revert of a multi-commit feature is verified file-by-file: `git diff` the post-revert tree against the last pre-feature commit for every path the feature touched; any intentional residue is named in the revert PR."* Mechanical alternative considered and rejected: a generic revert-completeness check can't know intent (some files legitimately keep changes); the quarantine-test pattern (a test that pins the reverted-to state AND self-flags when the feature's producer reappears) is the per-case mechanical complement, demonstrated in #231.

## Runtime discoveries (reference; no action required)

- kubectl rejects `TYPE.group/version NAME` client-side ("no need to specify a resource type as a separate argument") — the type form is `kind.version.group`.
- v2 XRs: `.spec.resourceRefs` is empty; refs live at `.spec.crossplane.resourceRefs` (live + render fixture).
- `aws --output text` booleans are `True`/`False` (Python capitalization).
- ESO with `deletionPolicy: Delete` **deletes** the target Secret when the remote key vanishes (status `SecretDeleted`, Ready=True — Ready does not mean "secret exists").
- Keycloak 24: strict Jackson realm parsing (unknown fields abort import; only `config`/`attributes` accept arbitrary keys); IdP URLs validated at import time; behind an L4-TLS NLB the issuer follows `X-Forwarded-Proto` unless `KC_HOSTNAME` is set.
- `argocd --core` reads `argocd-cm` from the kubeconfig context namespace — set the context namespace to `argocd` first.
- mikefarah yq emits `---` separator lines in raw multi-doc output (affects `while read` loops).
