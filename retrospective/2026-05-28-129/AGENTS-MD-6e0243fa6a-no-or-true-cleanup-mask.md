# agent instruction

**Never silence cleanup failures with `|| true`.** Test and CI cleanup steps that depend on succeeding (re-applying state, deleting resources, restoring config) MUST fail loudly when they fail. The `|| true` shell idiom masks the underlying error and lets contamination propagate to subsequent scenarios. If a cleanup is genuinely best-effort, guard with `[ -f X ] && cmd` or an explicit `if ! cmd; then echo WARN; fi` so the warning surfaces.

*Grounded in: 2026-05-28 PR #129 composition-drift — the original cleanup ran `kubectl apply -f crossplane/compositions/platform-secret.yaml || true` with a path that didn't resolve from chainsaw's CWD; the `|| true` masked the error and cascaded into three downstream scenario failures.*

# justification

The composition-drift scenario's "restore the Composition (cleanup)" step had been live for weeks. The line was `kubectl apply -f crossplane/compositions/platform-secret.yaml || true`. Chainsaw runs scripts from `tests/chainsaw/` (where `tests/chainsaw/run.sh` cd's), so the relative path resolved to a non-existent location. The kubectl call emitted `error: the path "crossplane/compositions/platform-secret.yaml" does not exist` to stderr; the `|| true` swallowed the exit code. The mutation persisted on the on-cluster Composition. Every subsequent scenario in the same chainsaw run (`claim-creates-secret`, `claim-rotation`, `claim-deletion-cleanup`) reconciled against the mutated composition and timed out their golden asserts at ~250 seconds each — 750+ seconds of CI wall-clock burned to surface a bug that would have failed the cleanup step in 2 seconds with `set -eu` and no `|| true`. The marginal cost of dropping `|| true` is: real failures show up as red exit codes in the right step, which is the point of having distinct steps. The cost of keeping `|| true` is the same multi-round chainsaw iteration loop that AGENTS.md §6.13 / §6.18 were written to prevent. For genuinely best-effort steps (cleanup of optional resources), the guarded form `if ! cmd; then echo WARN; fi` makes intent explicit; `|| true` does not.
