## Lessons (durable)

### L1 — A test that "skips when the fixture is absent" can silently NEVER run

The single most important technical finding. `tests/unit/test_composition_render_fixtures.sh`
skipped both the render-match AND determinism sub-tests whenever
`expected.yaml` was absent — and `expected.yaml` was **never bootstrapped**
for either XRD. So for the entire life of phase 2, the SPEC-S9 author-time
render gate **never executed even once**, and it hid a real determinism bug
in `scripts/composition-render.sh` (non-deterministic doc ordering +
non-idempotent re-normalization). "The XRDs were not working" had, as a major
component, "the gate that would prove the XRDs work had never run." A
skip-when-absent fixture test with no enforced bootstrap is a **coverage
hole that looks like coverage**. → see AGENTS-MD candidate below.

### L2 — When the user is actively present and asks a direct question, answer BEFORE more tool work

Mid-run the user asked several pointed questions ("What cluster are you
using?", "how did you not catch the stale creds?"). I kept making tool calls
across several turns before answering, and the user grew visibly frustrated.
In an interactive stretch, a direct user question is a higher-priority
interrupt than continuing the current tool chain. → AGENTS-MD candidate.

## Proposed AGENTS.md additions (full text + justification)

### AGENTS-MD: precondition-gated tests must FAIL (or assert bootstrap), not silently skip

# agent instruction

When a test skips its core assertions because a required fixture/golden is
absent (e.g. `expected.yaml` not yet bootstrapped), the same test MUST also
assert that the fixture *exists* — i.e. a missing golden is a FAILURE, not a
silent skip — UNLESS the absence is itself a deliberate, documented
allowlist entry. A "skip-when-absent" branch with no companion
"the fixture must eventually exist" gate lets a whole layer of coverage
never run. When you add a fixture-driven test, either (a) commit the fixture
in the same PR so the assertion runs immediately, or (b) add an explicit
xfail/TODO list the test checks against, so an un-bootstrapped fixture is
visible in CI rather than green-by-skipping.

# justification

In auto-004, `tests/unit/test_composition_render_fixtures.sh` skipped the
render-match and determinism sub-tests whenever `expected.yaml` was absent.
Neither XRD's golden was ever bootstrapped, so the SPEC-S9 render gate never
executed for the life of phase 2 — and hid a real determinism bug. The test
was "green" while testing nothing. Cost: phase-2 Compositions shipped without
the author-time validation they were supposed to have.

### AGENTS-MD: answer a present user's direct question before continuing tool work

# agent instruction

When the user sends a direct question while you are mid-task AND they are
evidently present (rapid successive messages), answer the question in chat
before issuing further non-trivial tool calls. Batching the answer behind
several more tool turns reads as ignoring them. Quick read-only calls needed
*to answer accurately* are fine; unrelated work is not.

# justification

In auto-004 the user asked several direct questions during an interactive
stretch; the agent continued tool chains across multiple turns before
replying, and the user escalated ("how in the world did you not catch…").
Prompt answers preserve trust and let the user redirect early.
