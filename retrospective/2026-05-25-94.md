## Part 3 — durable lessons (proposed agents-md rules / skills / ADRs)

### Part 3.1 — proposed AGENTS.md rules

#### AGENTS-MD-a — Subagent Write tool with absolute paths leaks to main worktree

The strongest run-defect: every implementation subagent's `Write` tool calls used absolute paths under `/home/user/k8-platform`. The Agent harness's `isolation: "worktree"` setting created proper isolated worktrees under `.claude/worktrees/agent-*/`, but the subagents' Write tool with absolute paths bypassed isolation and clobbered the main worktree. Subagents that ALSO used `git add` from their isolated worktree got the right files in their worktree (because the Write was followed by another Write at relative paths, or by `git add -A` which read from the isolated worktree's cwd) — but the leaked main-worktree copies caused stop-hook noise for the entire run and would have caused real damage if I'd committed them.

**Proposed rule (full text in `agents-md-a-isolated-worktree-relative-paths.md` sibling file):**
> When dispatching a subagent with `isolation: "worktree"`, the brief MUST instruct the subagent: "Your cwd is your isolated git worktree. Use repo-relative paths from cwd for all Write / Edit / Bash operations. Do NOT use absolute paths under `/home/user/<repo>` even if the brief mentions them — convert those to the matching relative path from your cwd. Verify with `pwd` if unsure."

### Part 3.2 — proposed skills

#### SKILL-SPEC-b — `subagent-chainsaw-dispatch`

Three subagents (A4, S9 CI-fix, C4) all hit the same wall: AGENTS.md §6.7 requires dispatching `chainsaw.yml` before opening a PR that touches chainsaw paths, but subagents either had no `gh` CLI, no `ext-github` wired through, or ran out of time waiting for chainsaw to finish (chainsaw takes 5–10 minutes; subagent budget was 60–90 min total). They all opened the PR anyway with the verifier failing — which is the right partial-credit move but means the lead has to chase every chainsaw-touching PR.

**Proposed skill:** wraps the dispatch + poll + open-PR-on-green sequence for chainsaw specifically. Either invoked by subagents (if they have authority) or by the lead agent as a follow-up step after each chainsaw-touching subagent reports done. Includes a check-once-on-completion path so subagents don't burn their budget polling.

#### SKILL-SPEC-c — `harness-checks-tool-availability-up-front`

Every subagent that needed Task / Agent dispatch (for the §6.4 adversarial-test-plan reviewer) discovered mid-task that it wasn't available, then self-reviewed inline. The Task tool not being exposed to sub-environments was a structural property of this harness, not a per-run accident.

**Proposed skill:** before authoring tests, the subagent runs a one-line tool-availability check ("can I dispatch a sub-subagent?"); if no, immediately switches to inline-review mode and notes it in the PR body without trying first.

### Part 3.3 — proposed ADRs

#### ADR-d — Adversarial review in autonomous runs when Task tool is unavailable

The autonomous-run skill mandates 2 rounds of ≥3 real-subagent adversarial reviewers at every decision-brief moment, citing AGENTS-MD-d72e1a4f3c as the source rule. In this run, **zero formal adversarial reviewers were dispatched** because the Task tool was not exposed to subagents. Every subagent self-reviewed inline. Lead agent never wrote a decision brief because the 3 decision points (D1, D2, D3) were resolved by subagents inline (or never materialized).

This means the run's decisions have only been challenged by single-thread self-review — not by independent cold-context reviewers as the skill mandates. The user should consider whether to:
- (a) Accept the inline self-reviews as adequate (cheap; acceptable for these decisions because they're all reversible and low-stakes);
- (b) Spin retroactive adversarial reviewers on D1 (wait-for-claim dump stream) and D3 (catch-block truncation) before merging the relevant PRs;
- (c) Refuse to merge any of the affected PRs until the harness offers Task to subagents and they can dispatch real reviewers.

**Recommendation (the lead agent's, for what it's worth): (a)** for D1 (trivially reversible — affects one log line stream redirect), **(b)** for D3 (catch-block truncation is global and affects every red chainsaw run from now on; cost of spinning one reviewer is low).

## Part 7 — what worked

- **Parallel Wave 1 dispatch (7 subagents).** Wall-clock from dispatch to all-PRs-open was ~25 minutes. Without parallelism this would have been hours.
- **Worktree isolation for git operations** (despite the absolute-path leak — see Part 3.1). Each subagent's `git add` and `git commit` operated cleanly on its isolated worktree's file tree; the PRs that opened had clean diffs.
- **Stacked PR pattern.** PR-1.S5 (#89) stacking on PR-1.S4 (#86), PR-2.S2 (#92) on PR-2.S7 (#88), PR-2.C4 (#94) on PR-2.A4 (#91) — all worked. The branches existed before their children were dispatched (Wave-2 timing held), and the auto-retarget behavior on GitHub will Just Work as parents merge.
- **Subagents' inline adversarial self-review.** When Task wasn't available, subagents wrote out what an adversarial reviewer would have asked + their answer. This isn't as good as real reviewers, but it's structurally honest and produced real test additions (~5 extra tests beyond spec §6 per subagent on average).
- **The scope-envelope-first protocol from the autonomous-run skill.** Catching alignment up front prevented later "wait, that's not what I meant" rework.

## Part 8 — what didn't work

- **Subagent absolute-path leaks.** See Part 3.1.
- **Subagents waiting on chainsaw inside their time budget.** A4 and S9's CI-fix subagent both timed out waiting for chainsaw to complete. The chainsaw heavy workflow takes longer than a reasonable subagent budget.
- **No real adversarial review subagents.** See Part 3.3.
- **Stop-hook false positives.** Every turn for the duration of the run, the stop hook fired complaining about untracked subagent leaks. The hook is correct in spirit (untracked files DO need attention) but in this run the right answer was "these belong to subagent isolated worktrees" — the hook can't tell. Could be configured to ignore patterns under `.claude/worktrees/` and known subagent-leak paths.

## Part 10 — late-breaking: A4 chainsaw real failure

Discovered at run-end: PR #91 (A4)'s chainsaw run actually **failed** (not just timed out — run 26418951701 completed `failure` at 20:55:45). The most plausible cause: the GitHub Actions `chainsaw.yml` workflow likely invokes the `chainsaw` CLI directly across `tests/chainsaw/**`, **not** through the repo's `tests/chainsaw/run.sh` (which A4 modified to invert exit code for `meta-*` scenarios). So the meta-test (`tests/chainsaw/meta-catch-fires/` — designed to fail to prove the catch hook fires) reports as a real chainsaw failure under the workflow.

Two fixes possible:
- (a) Have `chainsaw.yml` use `bash tests/chainsaw/run.sh` instead of invoking `chainsaw` directly — keeps meta-test inversion logic in one place.
- (b) Move the meta-test outside chainsaw's auto-discovery path (e.g., under `tests/chainsaw/_meta/` excluded by an `--exclude-test-regex` flag in the workflow).

(a) is structurally cleaner but touches the workflow. (b) is more localized.

**Implication:** PR #91 (A4) and the stacked PR #94 (C4) are both BLOCKED until this is resolved. The morning user should pick a fix path and have a follow-up session apply it.
