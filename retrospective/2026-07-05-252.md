### Phase 4 — build #4, the defect flush (#245, #248, #250, #251)

Build #4 was the first build with **no masking mid-build merges**, and
it flushed four latent committed defects, every one invisible to every
pre-live layer, each fixed red-first with zero hand-fixes:

1. **Kubeconfig truncate race (#245).** Management apply failed twice
   with one signature (own `update-kubeconfig` succeeds → next kubectl
   falls back to `localhost:8080`) on two victims. Eleven local-exec
   provisioners shared one truncate-rewritten kubeconfig at terraform
   parallelism 10. Builds #1–#3 won the timing. The red-first lint
   found 11 sharers where my manual audit had found 6.
2. **Producer-RBAC bootstrap ordering (#248).** The ADR-0010 producer's
   RBAC lived in auto-synced `crossplane-resources` but targeted the
   namespace created by the *manual* claim gate ~15 min later; the
   bootstrap sync exhausted its 5 retries and sat Failed until an
   unrelated commit would retrigger it — which every prior build had
   provided. The registration Secret never appeared. Moved the RBAC to
   ride the claim app beside `00-namespace.yaml`; lint mirrors the
   app's include/exclude globs, drift-guarded.
3. **Tag-charset rejection (#250).** With RBAC fixed, the chain's
   containers failed `CreateSecret`: "Request rejected by the
   downstream tagging service". The Composition patches
   `spec.description` into a tag; both committed keycloak XR
   descriptions carried parentheses (one a comma). Chainsaw had passed
   the same Composition twice that day — its scenario descriptions are
   paren-free. Renamed + charset lint over every tag-bound committed
   value.
4. **IAM observe gap (#251).** With tags fixed, creates succeeded, the
   SecretVersions wrote AWSCURRENT — and the container MRs stuck
   Synced=False: upjet's Secret *read* path calls
   `secretsmanager:GetResourcePolicy`, absent from the narrowed IRSA
   policy. Chainsaw runs on admin CI creds; only live IRSA exercises
   the narrowed policy. Fixture-first red → Sid → applied by
   management run 28755969208 → both XRs went Ready.

The four defects partition perfectly: chainsaw validates composition
logic under admin creds with test content; live validates IAM and
committed content. Neither substitutes for the other.

## Part 3 — remedies (classified per `ai/LESSONS.md` §3)

**(a) Mechanical — ALREADY SHIPPED this session** (each landed green
in the defect's own PR; LESSONS register rows L34–L36 added in this PR):

1. `tests/unit/test_tf_provisioner_kubeconfig_isolation.sh` (#245) —
   no kubeconfig path shared across provisioner blocks; writer/reader

2. `tests/unit/test_crossplane_resources_namespace_bootstrap_safe.sh`
   (#248) — auto-synced crossplane-resources manifests may target only
   bootstrap-guaranteed namespaces; mirrors the app's include/exclude
   globs with a drift guard.
3. `tests/unit/test_aws_tag_value_charset.sh` (#250) — every tag-bound
   committed value (XR descriptions everywhere + Composition tag maps)
   against the AWS tag charset.
4. Enforcement-cell change: `secretsmanager:GetResourcePolicy` in
   `tests/unit/fixtures/iam/crossplane-aws.txt` (#251) — the existing
   `test_iam_required_actions.sh` now pins the upjet observe path.

**(a) Mechanical — PROPOSED, not yet built:**

5. **Make `scripts/sandbox-setup.sh` best-effort per tool.** Today one
   403 on the first download aborts every later install under
   `set -e`, silently (the hook prints only the first tool's line).
   Design: wrap each tool's install in its own `if ! ( … ); then
   failed="$failed <tool>"; fi` subshell; always continue; print a
   FAILED summary line at the end and exit 0 (the suite's
   `require_tool` guards already fail closed per-test). Cost: ~20
   lines. This session lost ~30 minutes rediscovering which tools were
   missing one `command -v` at a time.

**(b) One-line AGENTS.md judgment-rule candidates (owner decides;
budget-aware):**

6. **Gate pulls after app-spec changes.** Proposed line for the Git
   and phases section: "A merged change to `argocd/apps/*` reaches the
   live Application spec only when bootstrap syncs it; verify the live
   spec (or sync bootstrap) before pulling a deliberate-sync gate, and
   sync gates by explicit SHA, not branch name." Grounding: two wasted
   gate pulls (~15 min + diagnostic confusion) on build #4 — first
   sync resolved a stale `main` from the repo-server cache, second ran
   before bootstrap had propagated the include-list change. L37 row
   added as proposed.
7. **Answer the question in the turn the facts arrive.** Proposed line
   for Evidence and communication: "When the owner asks a direct
   question, answer it in the same turn the facts are available —
   never park the answer behind unrelated mechanics (merges, waits)."
   Grounding: the owner had to demand the final accounting that was
   answerable one turn earlier. Cheap to follow; the cost of violating
   it is owner trust.

**(d) Observations, no action:**

8. Chainsaw's two blind spots (admin creds → IAM invisible; test
   content → committed-content classes invisible) are now partially
   compensated by remedies 3–4; the general fact is recorded in
   `ai/environment.md` §8 in this PR. A "crippled-creds chainsaw
   variant" was considered and rejected as a remedy here — the live
   loop IS the IAM oracle, and duplicating IAM simulation in chainsaw
