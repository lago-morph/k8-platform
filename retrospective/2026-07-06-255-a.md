## Part 3 — remedies (classified per `ai/LESSONS.md` §3)

### 1. ESO CRD-defaulted enums inside arrays — mechanical check (ADOPTED, this PR; L40)

Classification (1): `test_externalsecret_antidrift_enums.sh` scans every
ArgoCD-synced tree (`platform-services/`, `argocd/`) and requires the
three enums pinned on every `data[].remoteRef` and `dataFrom[].extract`;
fails closed on the unhandled `dataFrom[].find` form; carries a bad/good
selftest; enumerated in `run.sh` (the L30 completeness guard caught the
initial omission). Shipped green in the same PR as the fix. Registered
as **L40**.

### 2. sandbox-kubeconfig tunnel flap — mechanical fix (ADOPTED, this PR)

Classification (1): the script started a fresh SSM session per
invocation while setsid'd tunnels outlive their shells — the second call
could never bind the port, FATAL'd, and its cleanup overwrote the
pidfile, orphaning the *working* tunnel so every retry flapped. Now it
probes the port first: answering + kubeconfig present ⇒ reuse
(re-tracking the holder's pgid so `--stop` works); answering with no
kubeconfig ⇒ kill the orphan and start clean. Five cases live-tested
(reuse-eval, reuse-exec, stop, fresh start, immediate re-eval — the
exact flap).

### 3. Run-ID commits under exact-HEAD gates — documentation (ADOPTED, this PR)

Classification: method with >5 lines of nuance → documentation.
`ai/testing-guidelines.md` §7.1 now states the fixed order (content
commits finalized and pushed → dispatch at exact HEAD → run IDs recorded
afterward as docs-only commits) and the corollary that pre-recording an
ID for a not-yet-green run is a fabrication. Grounded in the #255
session's §3.4 mishaps 1–2 (the fabricated-ID near-miss and the
staged-docs sweep); complements — and cross-references — the proposed
`gated-branch-endgame` skill (SKILL-SPEC-e5a4cbc0c3), which would
automate the same choreography.

### 4. "Retro owed" briefs must be checked against origin before authoring — skill amendment (ADOPTED, this PR)

Classification (1), scoped to the skill: this session authored a full
retro for #255 because the briefing listed it as owed — while the #255
session's own retro was already merged (#257). The `self-retrospective`
Step 0.5 scope check only inspects the *current branch*
(`git log origin/main..HEAD -- retrospective/`), which is blind to
another session's retro on main or in an open PR. Amended Step 0.5:
before authoring, fetch and check `origin/main` (and open PRs if
reachable) for a retro whose filename anchors to the same PR number;
if found, scope down to an addendum (`-a` suffix) covering only material
the existing retro cannot contain. The same class hit the #255 session
itself (its brief listed the #243–#252 retro as owed when #253 had
already delivered it) — twice in two sessions is a pattern, and the
check is two commands.

### 5. Scheduled-work predictions in session-end records — observation (no rule)

Classification (4): the briefing asserted the 02:16Z trigger "fired —
read its outcome"; the trigger store showed it unfired because the
successor session started inside the arming window. Verify trigger
state (`last_fired_at` / `ended_reason`) before assuming a prior
session's scheduled work happened, and delete a taken-over trigger so
the old session cannot wake into duplicate work. Cost this time: near
zero (caught at orientation).

## §3.4 — operational mishaps

1. **The duplicate retro.** A full retrospective for #255 was authored
   from the session-end record before discovering #257 had already
   merged the #255 session's own, richer, first-person retro at the
   same target filename. Root cause: the briefing asserted the retro
   was owed, and the skill's scope check cannot see another session's
   work on main. Cost: one authored-then-demoted report plus a
   reconciliation rebase (L38/L39 collision, add/add on the retro
   path). Remedy 4 makes the origin check part of the skill.
2. **`git checkout --theirs` during a rebase selects the wrong side.**
   During the add/add resolution, `--theirs` selected *my* replayed
   commit (in a rebase, HEAD is the new base, so "ours" is main).
   Caught by checking the file's H1 before staging; recovered via
   `git show origin/main:<path>`. Know the inversion before resolving.

## §3.7 — runtime discoveries

- **A branch push can be rejected for `workflow` scope with zero
  workflow changes in the pushed commits**: if main's workflow files
  moved after the branch was cut, the new ref's workflow file *state*
  differs from main's current state, and the OAuth rule rejects the
  push. Fix: rebase onto current main (no jentic bridge needed unless
  the branch itself must change a workflow file).
- **The 02:16Z-class one-shot triggers survive their session's
  supersession**: `list_triggers` is the ground truth (`last_fired_at`,
  `ended_reason: run_once_fired`), and a fired one-shot advances
  `next_run_at` by a day while staying disabled-by-reason — an unfired
  one shows neither field.
- **Keycloak Bitnami chart admin API access**: the admin user is
  `admin` here (only `KEYCLOAK_ADMIN_PASSWORD` is set via env; the
  Secret key is `admin-password`); token via
  `POST /realms/master/protocol/openid-connect/token` with
  `client_id=admin-cli`, `grant_type=password`.
