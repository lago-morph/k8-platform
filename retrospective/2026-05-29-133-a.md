## Part 3 — agents-file suggestions

### Suggestion 1: Crossplane v2 has no claims — use XR / composite-resource terminology — `AGENTS-MD-1545d62c89`

- **Per-rule file**: [./2026-05-29-133-a/AGENTS-MD-1545d62c89-v2-no-claims-xr-terminology.md](./2026-05-29-133-a/AGENTS-MD-1545d62c89-v2-no-claims-xr-terminology.md)

**Proposed agent instruction** (verbatim from the per-rule file's `# agent instruction` section):

> **Crossplane v2 has no claims — say "XR" / "composite resource", not "claim".** "This repo runs Crossplane v2 (`apiextensions.crossplane.io/v2`, `scope: Namespaced`), which has NO claim CRD and no claim→XR promotion: `XPlatformSecret` / `XPlatformCluster` are namespaced composite resources (XRs) the user applies directly. In commentary, commit messages, PR text, and docs, call them the XR or the composite resource, never the claim. Some artifact names still contain `claim` as v1-era holdovers (the chainsaw scenarios `claim-creates-secret` / `claim-rotation`, the step `wait for claim Ready`, the file `clusters/platform/platform-cluster-claim.yaml`, and the ArgoCD Application `platform-cluster-claim`) — quoting those proper names verbatim is fine, but do not let `claim` leak into conceptual descriptions of how the resource works."
>
> *Grounded in: auto-004 — the agent repeatedly called the v2 XRs "claims" in running commentary; the user challenged it.*

**Justification** (verbatim from the per-rule file's `# justification` section):

The v1→v2 migration was a large, deliberate effort precisely to remove the claim/XR split, and the codebase documents this in many places ("v2 has no claim CRD", "the XR is applied directly"). An agent that keeps narrating "the claim provisions a cluster" signals it hasn't internalized the model the team spent weeks adopting, which erodes user trust — in this session the user stopped the run to challenge the terminology. The leak is easy because legacy *names* (`*-claim.yaml`, `claim-rotation`, "wait for claim Ready") still litter the test and GitOps surface, so the wrong word is constantly in front of the agent. The marginal cost of the rule is zero (it's a vocabulary choice); the cost of ignoring it is repeated, credibility-damaging mislabeling of the central abstraction of the platform. A secondary benefit: the rule flags the surviving `claim` names as a latent cleanup (rename to `*-xr`), so the tripwire itself can eventually be removed.
